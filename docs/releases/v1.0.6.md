### 2. 改善 Feign 主体名称日志

`g2rain-starter-feign-plus` 在请求与响应的 Debug 日志中，对主体名称及组织名称 Header 的日志副本进行 URL 解码，便于读取中文名称。

- 仅对 `x-name`、`x-organ-name` 对应值进行解码。
- 不回写请求模板或响应原始 Header，不改变实际传输编码。
- 这不是通用敏感信息脱敏功能；生产环境开启 Debug 日志前仍需检查 Header 与正文记录范围。

### 3. 收紧登录主体有效性判断

`g2rain-starter-web-infra` 的登录守卫按会话类型读取主体 ID，要求 ID 存在且大于零：

| 会话类型 | 校验字段 |
| --- | --- |
| USER、ANONYMOUS | userId |
| PASSPORT | passportId |
| MEMBER | memberId |

无有效主体 ID 时返回未认证错误。方法显式使用 `@LoginGuard(require = false)` 时仍跳过此登录校验；既有后台调用、非 Controller 方法及非 REQUEST 派发的处理分支保持。

本次新增 ANONYMOUS 会话具备正数 userId 时通过、缺少 userId 时拒绝的回归测试，并更新注解文档中对旧 anonymous 参数的描述；当前注解仅提供 require 属性。

## 升级注意事项

1. **不是无条件向下兼容的依赖替换。** Spring Boot、Spring Cloud、Jackson、MyBatis 与 Redisson 均有基线变化，业务应用须核对依赖树、配置和自动配置结果。
2. **匿名会话行为有变化。** v1.0.5 的 ANONYMOUS 分支直接放行；本次要求正数 userId。无主体的公开接口需要明确设计认证策略。不要为绕过失败而批量关闭登录守卫。
3. USER 与 PASSPORT 从“非空 ID”收紧为“正数 ID”，需要检查零值或负值占位数据。
4. MyBatis 数据隔离、Redis/消息、远程服务和链路追踪需要在实际环境联调；本次没有完成这些集成验证。
5. SpringDoc 模块在本次比较范围内没有新增，不能把已有模块误写成本版新功能。
